# BRODUN 스프린트 1 에셋 패키지

에셋 담당: 박정완 / 팀: 셔플 / 제작일: 2026-09-29

이 패키지는 최신 PRD의 3구역 테마와 통합 BattleScene 구성을 위한 스프린트 1 시각 자료다. 압축을 풀고 `preview.html`을 브라우저로 열면 게임 시작, 캐릭터 선택, 카드 전투, 적 피격, 승리·보상, 맵 복귀까지 직접 조작할 수 있다. 별도 서버나 인터넷 연결은 필요 없다.

## 플레이 미리보기와 영상 촬영

1. `preview.html`을 Chrome 또는 Edge로 연다.
2. **게임 시작**을 누르고 전사·마법사·사제 중 하나를 선택한다.
3. 전투에서 공격 카드를 누르면 캐릭터 공격 모션, 카드 속성별 투사체, 적 피격 모션과 HP 감소가 차례로 재생된다. 방어 카드는 방어막과 방어도를 만든다.
4. 행동력을 모두 사용하면 **턴 종료**를 누른다. 적 공격 후 행동력 3으로 다음 턴이 시작된다.
5. 적 HP가 0이 되면 승리·보상 화면이 나오고 보상 선택 뒤 맵으로 돌아간다.
6. 상단의 **촬영 모드**를 누르면 도구 영역을 숨긴 16:9 게임 화면만 표시된다. `Esc` 또는 `F`로 종료한다.

빠르게 전투만 촬영하려면 시작 화면의 **전투 바로 보기**를 사용한다. 전투 수치와 카드 구성은 기능·연출 확인용 임시값이다.

Backgrounds 외의 위 상대 경로는 모두 Assets/BRODUNArt 아래다. 배경은 실제 1672×941 PNG, 캐릭터·몬스터 시트와 아이콘 시트는 1280×1280 RGBA PNG다. 아트는 픽셀 스타일의 생성 이미지로, 32×32 또는 64×64의 엄격한 원본 도트 규격은 아니다. 원본 크기와 투명도를 보존했다. 타일맵용 반복 타일이나 레이어별 배경은 포함하지 않는다.

주인공은 오른쪽, 몬스터는 왼쪽을 향한다. 반대 방향은 SpriteRenderer.flipX로 사용할 수 있다. 위·아래 방향 전용 애니메이션은 없다. 3구역은 각 1개 배경을 공유하고 방 유형과 방문 상태는 UI로 표현한다. 구역당 10개 방에 모두 다른 배경을 만드는 구성은 아니다.

## 애니메이션 규격

|시트 행|파일 이름|동작|권장 FPS|반복|
|---|---|---|---|---|
|1|idle_00 ~ idle_03|대기와 호흡|6|예|
|2|walk_00 ~ walk_03|이동|8|예|
|3|attack_00 ~ attack_03|공격 또는 주문 시전|10|아니오|
|4|hurt_00 ~ hurt_03|피격과 회복|10|아니오|
|5|death_00 ~ death_03|쓰러짐|7|아니오, 마지막 유지|

각 행은 왼쪽에서 오른쪽 순서다. 원본은 4열×5행이지만 공격 효과가 정규 격자 경계에 가까운 곳이 있어 **Frames의 분리된 PNG 사용을 권장**한다. 투명 여백을 검사해 자른 실제 좌표, 크기와 pivotX/pivotY는 manifest.json에 기록했다. 고정 크기 프레임이 아니므로 파일별 pivot을 적용한다. 생성 특성상 호흡·보행의 형태 변화와 미세한 흔들림이 남아 있으며 최종 출시용 수작업 애니메이션 정리는 별도 단계다.

공격 이미지에 표시된 빛은 연출이다. 사제의 금빛 연출은 새 '빛' 속성을 추가하는 규칙이 아니며 카드 데이터의 속성과 구분한다. 보스 전용 시트는 이번 패키지에 없고, 스프린트 1 보스 노드는 아이콘으로 나타낸다. 통합 BattleScene의 보스 연결 시연에는 파수병을 임시 외형으로 재사용할 수 있으나 최종 구역 보스 디자인으로 확정한 것은 아니다.

## Unity에 가져오기

1. 패키지의 `Assets/BRODUNArt` 폴더를 프로젝트의 `Assets` 아래에 복사한다. 같은 폴더가 이미 있으면 먼저 팀 변경사항을 확인하고 병합한다.
2. C# 컴파일이 끝난 뒤 상단 메뉴 `BRODUN > Art > Reimport and create animation clips`를 실행한다. 도구는 이 폴더 아래 PNG만 설정하고 Animations 폴더에 클립과 컨트롤러를 생성한다.
3. SpriteRenderer와 Animator를 **동일한 GameObject**에 추가하고 해당 캐릭터의 컨트롤러를 연결한다. 기본 상태는 idle이다. SpriteRenderer에는 idle_00을 넣는다.
4. 게임 이벤트에 따라 `animator.Play("attack", 0, 0f)`, `animator.Play("hurt", 0, 0f)`, `animator.Play("death", 0, 0f)`를 호출한다. 공격·피격 후 idle로 돌아오는 로직은 팀의 전투 상태 관리에서 연결한다. 컨트롤러에는 자동 전이가 없다.
5. UI 이미지에는 Frames/ui_icons와 UI의 PNG를 사용하고 카드 이름·설명·비용·HP 숫자는 TextMeshPro로 표시한다. hp_fill은 UI Image의 Filled 방식으로 수치에 맞게 변경한다. 카드/버튼은 제공된 종횡비를 유지한다. 9-slice 테두리 정보는 자동 설정하지 않는다.
6. 배경은 Single Sprite 또는 UI Image로 배치하고 16:9에 맞춘다. 16:10은 배경만 약간 자르고, 버튼·카드·HP는 Canvas 앵커로 유지한다. 구역별 바닥 높이가 달라 1200×675 미리보기 기준 캐릭터 발 위치 Y는 위에서 약 370 / 292 / 397이다.

자동 설정은 Point 필터, 압축 없음, Mipmap 없음, Pixels Per Unit 128, 원본 크기 유지, Full Rect를 사용한다. UI는 중앙 기준, 주인공·적의 분리 프레임은 manifest의 발 기준 pivot을 적용한다. 시트 전체는 참고용이므로 자동 분할되지 않는다.

Unity 에디터가 이 작업 환경에서 확인되지 않아 **Unity 실제 컴파일·Play Mode 검증은 수행하지 않았다**. 팀 프로젝트에서 가져오기, 클립 재생, 크기와 pivot을 확인해야 한다. 스크립트 API 참고: [Unity TextureImporter](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityeditor/textureimporter), [AnimationUtility](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityeditor/animationutility). 팀의 Unity 6.3 환경에서 최종 확인한다.

에셋 준비 완료와 스프린트의 기능 완료는 구분한다. 미리보기의 맵은 고정 배치 예시이며 시드 생성 테스트가 아니다. HTML 전투 데모는 콘셉트와 에셋 작동 영상을 촬영하는 용도이며, Unity 프로젝트의 실제 구현·테스트를 대신하는 증거는 아니다.

## 확정되지 않은 사항

구역 테마와 핵심 속성은 PRD 기준이다. 전사·마법사·사제는 이번 요청 기준이다. 세 몬스터의 이름과 외형, 캐릭터 복장, 예시 카드 9개, 예시 비용과 피해·방어·회복 수치는 이번 에셋 제작에서 제안한 임시안이다. PRD의 TBD를 확정하지 않는다. 시작 캐릭터 수나 비용 체계는 팀 결정에 맞춰 수정한다.

## 출처와 수정

배경·캐릭터·몬스터·아이콘은 이 요청을 위해 내장 image_gen으로 생성했다. 외부 에셋 스토어에서 다운로드한 상품은 없다. 프레임 분리는 원본 픽셀과 알파를 유지하는 기계적 추출이다. UI 틀은 코드로 제작한 SVG와 그 PNG 출력이며 SVG를 편집해 변경할 수 있다. `generation_prompts.json`에 생성 지시문을 보관했다. 원본 시트는 Sprites/UI에 그대로 포함되어 있다.
